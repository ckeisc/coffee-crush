Top-bar blur — isolation test

Open in Safari on iPhone on a fresh load. For each variant 1–6, note whether its top-bar text is SHARP or BLURRY. Compare with the plain label text above each frame — the label is the sharpness control. Screenshot the page.

Test: opaque status bar (black) · 2026-11-26

Note: the opaque status bar only takes effect as an installed PWA, not in Safari.

Variant 1 — CONTROL: exact v7 top bar over a live repainting canvas

Same bar, same plate, same CSS as Coffee Crush v7. The canvas behind repaints every frame, like the game board. If this is blurry and Variant 2 is sharp, the live canvas is implicated.

Verdict: SHARP / BLURRY

Variant 2: exact v7 top bar over a static plain background (no canvas)

Identical bar, but no canvas at all behind it. If this is sharp while Variant 1 is blurry, the repainting canvas is the cause.

Verdict: SHARP / BLURRY

Variant 3: exact v7 top bar over a canvas that is present but NOT animating

Same canvas as Variant 1, but drawn once and never repainted. If this is sharp while Variant 1 is blurry, the continuous repainting (not the canvas itself) is the cause.

Verdict: SHARP / BLURRY

Variant 4: top bar with the plate REMOVED — bare text over the live repainting canvas

No .topbar-bg plate at all; the text sits directly on the live canvas. If this is sharp while Variant 1 is blurry, the plate layer is implicated after all.

Verdict: SHARP / BLURRY

Variant 5: exact v7 top bar but NOT fixed — in normal document flow, static background

Same bar and plate, but position:static instead of position:fixed, over a static background. If this is sharp while Variant 2 is blurry, the fixed positioning / fixed layer is the cause.

Verdict: SHARP / BLURRY

Variant 6 — SANITY BASELINE: plain unstyled text, system font, no plate, static background

The same words with no styling at all. This one should always be sharp — if even this is blurry, the problem is not in the page at all.

Verdict: SHARP / BLURRY
